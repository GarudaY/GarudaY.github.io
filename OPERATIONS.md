# Local operations

Проект принимает регистрации и контактные обращения, сохраняет их и отдельно отслеживает отправку email-уведомлений. Ошибка почты не удаляет сохранённое обращение.

## Что работает

- серверная Zod-валидация и ограничение размера запросов;
- защита same-origin, honeypot и локальный rate limit;
- атомарное хранение в `.data/operations.json`;
- уникальность активной регистрации по `event + email`;
- подтверждение по доступным местам и автоматический waitlist;
- продвижение первой подходящей заявки из очереди после отмены;
- приватная ссылка просмотра и отмены;
- контактная очередь со статусами `new`, `in_progress`, `resolved`;
- локальная админка `/uk/admin` или `/de/admin`;
- CSV-экспорт регистраций и обращений.

Админка и экспорт отвечают только при открытии через `localhost` или `127.0.0.1`. На публичном hostname API возвращает `403`, а страница — `404`.

## Хранение и резервные копии

По умолчанию файл создаётся в `.data/` и исключён из Git. Путь можно изменить через `LOCAL_DATA_DIR`. Для реального self-hosted запуска каталог должен находиться на постоянном диске и регулярно копироваться.

Отменённые заявки и закрытые обращения удаляются при очередной записи через `LOCAL_DATA_RETENTION_DAYS` дней, по умолчанию через 30. Активные заявки и незакрытые обращения автоматически не удаляются.

Файловое хранилище подходит для одного локального или небольшого self-hosted Node-процесса. Оно не подходит для serverless-хостинга с временной файловой системой или нескольких параллельных серверов. В существующем Sites/Cloudflare-развёртывании используется постоянная D1-база через binding `DB`; обновления защищены проверкой ревизии. Без binding режим `HOSTED_DEMO=true` останавливает запись, а не подменяет базу временной памятью.

## Почта

`FORM_NOTIFICATION_TRANSPORT=smtp` включает настоящий SMTP-транспорт. `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD` и при необходимости `SMTP_FROM` задаются только на сервере. Порт 465 использует TLS сразу; для 587 и других портов обязателен STARTTLS. Реквизиты и пароль SMTP нельзя помещать в публичные переменные или Git.

По умолчанию общие вопросы отправляются на `kontakt@sonnenblume-mg.com`, курсы и события — на `kurse@sonnenblume-mg.com`, волонтёрство и вопросы правления — на `vorstand@sonnenblume-mg.com`. Адрес посетителя используется только как `Reply-To`. Выбранная волонтёрская роль включается в текст письма.

`notificationStatus=sent` означает, что почтовый транспорт принял письмо, а не гарантирует его появление во «Входящих»: доставку, спам и отложенные возвраты контролирует почтовый провайдер. Ошибка сохраняется как `failed` вместе с диагностикой; интерфейс не показывает ложное сообщение об успешной отправке.

Альтернативный `cf7`-транспорт требует отдельной настройки маршрутов в WordPress: поле `FORM_RECIPIENT_*` само по себе не меняет адрес получателя существующей формы Contact Form 7. В текущем развёртывании используется SMTP.

## Проверка

При запущенном `npm run dev` выполнить:

```bash
npm run test:operations
```

Изолированные проверки SMTP-маршрутизации и реального содержимого QR (без отправки писем):

```bash
npm run test:notifications
```

Скрипт временно резервирует текущий файл, проверяет регистрацию, duplicate-защиту, waitlist, автоматическое продвижение, отмену, контактную очередь, админский API и CSV, после чего восстанавливает исходные данные.

## Что намеренно не имитируется

- отправка SMS и подтверждение попадания email во «Входящие»;
- настоящие платежи;
- юридически утверждённые тексты согласий;
- публичная удалённая админка и управление пользователями.

Для этих функций нужны реальные аккаунты, реквизиты, политика доступа или внешний сервис.
