# Готовность почты, QR, CMS и staging

Обновлено 23 сентября 2026 года. Новый frontend и WordPress CMS работают на закрытом staging `https://staging.sonnenblume-mg.com/`. Production `https://sonnenblume-mg.com/` не переключался и остаётся прежним сайтом. Staging использует отдельную базу и каталог, закрыт HTTP Basic Auth и `noindex`; исходящая почта и внешние интеграции намеренно отключены.

## Реальная проверка почты

Три явно помеченных технических сообщения отправлены через опубликованный `/api/contact` с origin `https://garuday.github.io`:

| Тема         | Адрес                       | Номер обращения     | Результат           |
| ------------ | --------------------------- | ------------------- | ------------------- |
| general      | kontakt@sonnenblume-mg.com  | MSG-20260913-A75461 | HTTP 201, SMTP sent |
| courses      | kurse@sonnenblume-mg.com    | MSG-20260913-973C05 | HTTP 201, SMTP sent |
| volunteering | vorstand@sonnenblume-mg.com | MSG-20260913-31101A | HTTP 201, SMTP sent |

Это подтверждает приём писем SMTP-транспортом и работу CORS. Проверка папок «Входящие»/«Спам» и отложенных возвратов требует доступа к самим почтовым ящикам; её результаты не подменяются ответом API.

Пароль SMTP хранится как серверный секрет. Маскированное значение в настройках не означает, что пароль отсутствует. Для другого хостинга понадобятся те же секреты и постоянное хранилище — GitHub Pages не исполняет серверный код.

## QR для пожертвования

Старый PNG содержал только `BCD`; он больше не используется компонентом. Новый `bank-transfer-epc-qr.png` содержит полный EPC069-12 payload. Получатель и IBAN сверены с [официальной страницей пожертвований](https://sonnenblume-mg.com/spenden/), BIC — со [страницей банка](https://www.sparkasse-moenchengladbach.de/de/home.html). Формат — по [EPC069-12 v3.1](https://www.europeanpaymentscouncil.eu/document-library/guidance-documents/quick-response-code-guidelines-enable-data-capture-initiation).

Реквизиты, текст на странице и QR используют единый `src/config/donation-bank.json`. Сумма не задана: донор вводит её сам. Код нужно сканировать функцией своей банковской программы, поддерживающей EPC/GiroCode. Обычная камера телефона не обязана открывать банковский перевод. Платёж при проверке не выполнялся.

Автотесты расшифровывают именно публичный PNG, проверяют полный payload, IBAN checksum, отсутствие фиксированной суммы и считывание в мобильном размере 224px. `npm run generate:qr` пересоздаёт производный PNG после согласованного изменения реквизитов.

## Перед следующей публикацией

1. Выполнить `npm run lint`, `npm run typecheck`, `npm run test:pages`, `npm run test:notifications`.
2. Для GitHub Pages создать `.pages-out` через `npm run build:pages`; workflow выполняет это автоматически при push в `source`, вручную и каждые 15 минут, всегда собирая свежую ветку `code`. CMS/API остаются в WordPress.
3. Перед production включить и проверить `wp_mail()` на правильных адресах, оставив сохранение заявки независимым от результата почты. Не переносить staging-заявки как реальные.
4. После публикации убедиться, что новая картинка QR доступна по новому имени и старый закэшированный PNG не используется. Проверить один технический email и удалить/закрыть тестовые записи только штатными средствами после согласования.

Проверка email-routing и QR добавлена в GitHub Actions: невалидный PNG или сломанная маршрутизация остановят сборку до публикации.

## Готовность текущей локальной версии

На staging работают шесть WordPress CMS-модулей — новости, люди (правление, преподаватели, команда, активные волонтёры), курсы, события, волонтёрские вакансии и партнёры/благодарности. Импортированы 3 новости, 7 профилей, 4 курса, 6 событий, 4 вакансии и 7 партнёров с медиа. Статический frontend читает единый валидированный снимок этих feed. Пирамида правления и компактные горизонтальные преподаватели сохранены.

Плагин 0.7.0 добавляет WordPress-очередь обращений и регистраций. Проверены 39 schema/unit-тестов и 164 интеграционные проверки на disposable WordPress: вместимость, confirmed/waitlist, параллельные заявки, защита от повторов, приватная отмена и продвижение очереди. `snb_editor` видит очередь и CSV, `snb_author` — нет. Все общие DB-mutex и связи преподавателей/курсов продолжают проверяться.

Линтер, TypeScript, 7 проверок email/QR, 2 routing-теста, тест операций и тест статического экспорта прошли в текущем цикле. Тест доставки подтвердил, что production Next.js через HTTPS читает CMS, добавленную после сборки, а статический экспорт создаёт новые страницы людей, событий и волонтёрских задач на обоих языках. Его временные записи архивированы. `.pages-out` затем заново собран без CMS: 64 страницы, включая 8 страниц курсов, 12 страниц событий, 14 профилей и две страницы волонтёрства на двух языках; временных маркеров и локальных CMS-адресов нет. `.sites-bundle/dist` и `.sites-bundle/site.tar.gz` также пересобраны без локального CMS; в архиве есть Worker, hosting metadata, миграция D1 и PNG. Хеш QR в обеих сборках совпадает с источником.

Next.js обновлён до 16.3.5, Nodemailer — до 9.1.1. `npm audit --omit=dev` не выявил уязвимостей. В полном аудите остаются 4 moderate-предупреждения в dev-цепочке drizzle-kit/esbuild; принудительное понижение drizzle-kit ради их удаления не выполнялось. Уязвимый dev-сервер esbuild не запускается.

Проверенная версия опубликована на временном GitHub Pages по адресу `https://garuday.github.io/`; сборка берёт контент из закрытого staging CMS. Preview закрыт от индексации одновременно метатегом `noindex` и `Disallow: /` в `robots.txt`; workflow останавливается, если эта защита пропадёт. Production `https://sonnenblume-mg.com/` по-прежнему не переключён и остаётся старым сайтом. QR-исправление и обновления безопасности уже входят в Pages-сборку; существующие серверные секреты и аудитория production сохранены без изменений.
