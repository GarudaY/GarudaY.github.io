# SONNENBLUME — WordPress CMS и заявки

Рабочий плагин 0.7.0 для новостей, людей, курсов, событий, волонтёрских задач, благодарностей и операционных заявок. Правление, преподаватели, команда, активные волонтёры, учебные программы, афиша, вакансии и партнёры редактируются в одной панели. Плагин установлен на закрытом staging `staging.sonnenblume-mg.com`; production пока не переключён. Он не меняет тему старого WordPress, WooCommerce или пользовательские аккаунты. `/admin` нашего Next.js frontend остаётся локальным техническим экраном, рабочая очередь находится в WordPress → SONNENBLUME → Заявки.

## Что реализовано

- Структурированные новости на украинском и немецком, порядок и тематическая иконка.
- Фото из штатной медиа-библиотеки, переведённый alt и вертикальный фокус кадра.
- Сохранение рабочего черновика отдельно от публичного снимка.
- Передача редактору на проверку; публикация только редактором.
- Архивирование без уничтожения текста и восстановление последних 20 версий в черновик.
- Персональные роли `snb_author` / `snb_editor`; автор видит только свои записи.
- Серверная проверка каждого объекта и действия, nonce/cookie WordPress, ограничение загрузок, plain-text поля, контроль конкурирующих правок (409).
- Публичный API отдаёт только схвалённый снимок: без черновиков, истории и информации об авторах.

До 200 записей в каждой коллекции, на главной до 12 новостей. Это сознательный предел небольшого блока, не массовая новостная платформа. Опубликованные фото публичны; не загружать в медиа-библиотеку документы/фото, которые должны оставаться закрытыми. История хранит 20 редакторских снимков в метаданных, это не обещание неограниченного журнала или полного резервного копирования.

## Люди: второй реализованный модуль

SONNENBLUME → Люди: имя, роль, биография, отдельные преподавательские роль/описание, языки, порядок и фото, uk/de. Можно выбрать несколько ролей. Активному волонтёру необязательно состоять в Verein; такие люди появляются на главной. Преподаватели используют прежние компактные горизонтальные карточки.

Для правления есть явная позиция «Голова»/«Член правления». Только один опубликованный председатель; пирамида сохраняется, заголовок не зависит от числа людей. Для смены председателя сначала опубликовать предыдущего как обычного члена правления.

Адрес профиля латиницей фиксируется после первого сохранения навсегда, включая архив. ID `person-{slug}` сохраняет связи с существующими курсами. При публикации обязательны оба языка, отдельное преподавательское описание (для teacher), alt для фото и подтверждение редактором разрешения на публикацию. Это декларация редактора, не самостоятельный юридический реестр согласий. Приватные контакты в профили не добавляются.

Связи с курсами управляются в форме курса: преподавателя выбирают из опубликованных профилей с ролью teacher. Связанный преподаватель не может быть архивирован или лишён роли teacher, пока опубликованный курс на него ссылается. Сначала нужно переназначить преподавателя в курсе и опубликовать изменение; черновик курса сам по себе не ослабляет защиту.

Локальный запуск однократно импортирует семь текущих профилей и пять доступных реальных фото из проекта, не перезаписывая уже отредактированные записи. Наталия / немецкий и Ольга / арифметика сохранены. Отсутствующие портреты остаются инициалами — выдуманных лиц нет. Импортёр не входит в ZIP плагина и на хостинге автоматически ничего не засеивает. Архив скрывает профиль, но не удаляет файл медиа или копии кешей.

Публичный feed людей: `/?rest_route=/sonnenblume/v1/people/public`; закрытые `GET/POST .../people`, `.../people/{id}` используют те же действия/согласование, cookie/nonce и права на конкретный объект. Отдельная структурная блокировка предотвращает гонку одинаковых адресов и двух председателей. Публичный JSON не раскрывает подтверждения разрешений, учётные записи, черновики или историю.

Для людей нет fallback к старым данным при ошибке настроенного CMS: снятые профили не должны возвращаться. Корректный пустой feed остаётся пустым; ошибка останавливает соответствующий запрос. Без настройки CMS используется текущий локальный контент.

## Курсы: третий реализованный модуль

SONNENBLUME → Курсы: заголовок, краткое и полное описание, возраст, язык, формат, место, цена, длительность, результаты, материалы и расписание на uk/de. Отдельно задаются категория, статус набора, дата начала, информационное число мест, порядок, отметка избранного, преподаватели, связанные курсы, обложка, alt и фокус кадра.

Адрес курса фиксируется после первого сохранения и не переиспользуется даже после архива. Четыре существующих курса импортируются локально с прежними внутренними ID, адресами, обложками, порядком и связями с преподавателями. Это сохраняет действующие ссылки сайта. Импортёр не входит в ZIP и ничего не добавляет на сервере автоматически.

Публикация требует обоих языков, обложки, alt, результатов обучения и существующих опубликованных преподавателей. Связанные курсы выбираются из списка; публичный API не отдаёт незавершённые связи. Поле мест в курсе только информационное и не связано с регистрациями: фактическую вместимость событий и остаток мест по-прежнему считает сервер заявок.

Публичный feed курсов: `/?rest_route=/sonnenblume/v1/courses/public`; закрытые `GET/POST .../courses`, `.../courses/{id}` используют тот же цикл черновик → проверка → публикация → архив/восстановление. Для курсов, как и для людей, настроенный, но недоступный CMS не подменяется старыми данными.

## События: четвёртый реализованный модуль

SONNENBLUME → Події: отдельные украинские и немецкие название, анонс, текст, место, цена и подпись кнопки; дата/время, категория, статус (предстоящее, прошедшее, отменённое), обложка и галерея до 12 фотографий, alt и фокус для каждого кадра. Архивные афиши и отмены остаются доступными с честной подписью. Подписи даты/времени можно оставить пустыми или заполнить на обоих языках. Контактный email хранится как информационное поле, не как список получателей заявок.

Локальный импорт создаёт шесть нынешних событий с прежними ID/адресами и 12 различными реальными файлами (7 фотографий в галереях). Он выполняется однократно, не перезаписывает редакторские правки и не входит в ZIP плагина. Публичный feed: `/?rest_route=/sonnenblume/v1/events/public`; настроенный, но недоступный CMS не подменяется локальными событиями. Новые адреса на серверном frontend открываются без пересборки; GitHub Pages требует новой сборки.

Для предстоящего события редактор задаёт вместимость и начальный остаток мест от 0 до 500. Если вместимость больше нуля, frontend показывает полноценную запись. WordPress API атомарно распределяет подтверждённые места и waitlist, отклоняет повторы, выдаёт приватный токен статуса/отмены и при отмене продвигает следующего участника из ожидания. Отдельный advisory lock не допускает переполнения при одновременных запросах.

## Волонтёрские задачи: пятый реализованный модуль

SONNENBLUME → Волонтерство: короткие вакансии на странице «Долучитися» с отдельными названиями, описаниями, временем и местом на украинском и немецком, ограниченным набором пиктограмм и порядком. Задачи проходят тот же цикл черновик → проверка → публикация → архив; закрытая вакансия исчезает с сайта. Код задачи фиксируется после первого сохранения и используется в контексте заявки, поэтому его нельзя незаметно переименовать или повторно занять после архива.

Четыре нынешних варианта помощи импортируются в локальный WordPress однократно без перезаписи уже изменённых материалов; на сервере ZIP ничего не импортирует автоматически. Публичный feed: `/?rest_route=/sonnenblume/v1/volunteer/public`. Если опубликованных задач нет, на странице остаётся форма «Маєте іншу ідею?». Эта контентная панель не открывает редакторам письма и персональные данные волонтёров; они по-прежнему идут через отдельный серверный маршрут обращений.

## Партнёры и благодарности: шестой модуль

SONNENBLUME → Партнери: название организации либо имя отдельного помощника, благодарность на uk/de, необязательная HTTPS-ссылка, порядок и логотип/фото из медиа-библиотеки. Для организации логотип обязателен, для человека фото необязательно; перед публикацией человека редактор подтверждает согласие на публичное имя и фото. Это отметка, а не юридический реестр согласий. Публичный feed не отдаёт эту отметку, черновики, авторов и историю.

Семь нынешних организаций и их логотипы однократно импортированы только в локальный WordPress; SVG-логотип конвертирован в PNG для безопасной медиа-библиотеки. Нет вымышленных людей. Записи проходят черновик → проверку → публикацию → архив. Код после сохранения неизменен, совпадение с архивом запрещено. Снятая запись не восстанавливается из старого списка.

На настоящем WordPress ZIP ничего не импортирует. Пока редактор не внесёт и не проверит все нужные организации, сайт продолжает показывать нынешний список из кода. Затем только редактор нажимает «Замінити список на сайті» с предупреждением: это явно переключает весь блок на CMS и не может тихо произойти при создании первого черновика. После переключения даже пустой опубликованный список остаётся пустым. При ошибке настроенного CMS старые записи не возвращаются. Публичный feed: `/?rest_route=/sonnenblume/v1/partners/public`, закрытый endpoint переключения: `.../partners/activate`.

## Локальная работа

Из корня проекта: `npm run dev:cms` и `npm run dev:with-cms` в двух терминалах. Первое действие создаёт отдельную локальную установку WordPress Playground 7.1 / PHP 8.2; повторный запуск сохраняет данные. Записи-примеры добавляются однократно и не перезаписываются при рестарте. Установка слушает только loopback, включая стартовую фазу; одноразовая ссылка для входа выводится в терминал и действует час. Ссылка и стандартный Playground-аккаунт предназначены только для этой локальной установки.

Данные хранятся в каталоге сайта под `%USERPROFILE%/.wordpress-playground/sites/`, а не в Git. Helper `wp-content/mu-plugins/snb-local-preview.php` генерируется только локальным скриптом, отсутствует в плагине и **не должен попасть на хостинг**. На production только обычные WordPress аккаунты и HTTPS. Не копировать локальную БД/весь wp-content вместо установки плагина.

## Текущий staging и следующий этап

На `https://staging.sonnenblume-mg.com/` поднята отдельная копия WordPress в отдельной базе, закрытая HTTP Basic Auth и `noindex`. Реальная исходящая почта и внешние интеграции там отключены. Установлен плагин 0.7.0, перенесены 3 новости, 7 профилей, 4 курса, 6 событий, 4 вакансии и 7 партнёров с медиа. Сверху WordPress размещён статический frontend; `/wp-admin/` и REST API сохранены.

До production: провести пользовательскую приёмку, назначить каждому редактору персональную узкую роль, включить вместимость только у реально открытых событий, настроить production-почту и выполнить финальный backup непосредственно перед согласованным переключением. Не выдавать общий пароль administrator/KAS и не включать публичную регистрацию.

## API и доставка на frontend

Публичные read-only feeds: `/?rest_route=/sonnenblume/v1/updates/public`, `/?rest_route=/sonnenblume/v1/people/public`, `/?rest_route=/sonnenblume/v1/courses/public`, `/?rest_route=/sonnenblume/v1/events/public`, `/?rest_route=/sonnenblume/v1/volunteer/public` и `/?rest_route=/sonnenblume/v1/partners/public`. При pretty permalinks доступны соответствующие пути `/wp-json/sonnenblume/v1/.../public`.

Операционные endpoints: `POST /wp-json/sonnenblume/v1/contact`, `GET/POST /wp-json/sonnenblume/v1/registrations`, `GET/DELETE /wp-json/sonnenblume/v1/registrations/{token}`. Контактная форма маршрутизирует темы на `kontakt@`, `kurse@` или `vorstand@`; адрес получателя нельзя подменить из браузера. В базе хранится только SHA-256 приватного токена отмены. Персональные записи не выдаются публичным списком.

Закрытые endpoints: `GET/POST .../updates`, `GET/POST .../updates/{id}`. Native cookie + `X-WP-Nonce` (action `wp_rest`). Write actions: `save`, `submit`, `publish`, `archive`, `restore`; существующая запись требует числовой `revision`. Для restore нужен `targetRevision` из доступной истории. Отдельные `working/live` snapshots и compare-and-swap обновляются одной операцией metadata — изменение черновика не открывает его наружу.

Frontend не получает WP cookie/nonce/application password. Он читает только публичный JSON на сервере, валидирует схему/переводы/ID/порядок и разрешает фото только с origin CMS из `wp-content/uploads`. Содержимое не рендерится как HTML.

Для структурных связей людей, курсов и кодов волонтёрских задач используется общий DB-mutex через `INSERT IGNORE` и unique key `option_name`, условное освобождение только своего токена и проверка адресов, председателя и преподавателей по свежим данным БД. Обычный [`add_option()`](https://developer.wordpress.org/reference/functions/add_option/) не используется как блокировка: его SQL содержит `ON DUPLICATE KEY UPDATE`. Одновременное создание одинаковых адресов проверяется пятью парами реальных HTTP-запросов. После аварийно оборванного запроса блокировка истекает через 5 минут; до этого форма сохраняет несохранённый текст и предлагает повторить запрос.

Если настроенный CMS недоступен в серверной версии, только новости могут показать явно подписанные примеры. Люди, курсы, события, волонтёрские вакансии и активированный список партнёров не подменяются старыми mock-списками: локализованный error boundary предлагает повторить загрузку или связаться с нами. Старый список партнёров используется только до явного переключения коллекции. Пустой активированный feed не подменяется прежними записями. Статическая production-сборка с настроенным CMS при ошибке останавливается, чтобы не публиковать ложную версию.

GitHub Pages: workflow читает feed при сборке и автоматически запускается каждые 15 минут, при push в default-ветку `source` и вручную; исходники всегда берутся из `code`. Поэтому публикация обычного контента становится видна после следующей успешной сборки, а не мгновенно. Формы и регистрации обращаются к WordPress API напрямую и работают без пересборки. Не сохранять GitHub PAT в плагине.

При сборке Pages шесть публичных feed фиксируются один раз в проверенном снимке в изолированной `.pages-work`. Все страницы и новые адреса людей/курсов/событий строятся из одного снимка, а не из меняющегося CMS во время сборки. Runtime sitemap динамическая, для export генерируется отдельная static-конфигурация. Генераторы статических профилей, курсов и событий добавляются только в export-копию: серверные новые адреса должны открываться без пересборки.

## Проверки

`npm run qa:cms:publish` создаёт либо обновляет в локальном WordPress по одной полностью заполненной QA-записи каждого типа и публикует их. `npm run qa:cms:archive` снимает эти же записи с публикации в безопасном порядке зависимостей. Оба режима работают только с `localhost`/`127.0.0.1` и завершаются ошибкой, если видимость записи в публичном feed не соответствует ожидаемому состоянию. Это удобный повторяемый сценарий для ручной приёмки и скриншотов; на staging и production он намеренно не запускается.

`npm run test:cms` — 39 schema/unit-тестов и 164 проверки disposable WordPress 7.1 / PHP 8.2: роли, авторство, черновики/live, публикация, архив, параллельные сохранения, media upload, вместимость, confirmed/waitlist, повторные заявки, приватная отмена, продвижение очереди, маршрутизация контактов, хранение заявок, права редактора и очистка тестовых данных. Тест не обращается к старому сайту и не отправляет реальные письма.

`npm run test:cms:frontend` — локальный end-to-end с backend `127.0.0.1:9400` и frontend `localhost:3000`: тестовая запись проходит черновик → публикация → новый черновик → архив. Создаёт только маркированную тестовую запись в отдельной локальной БД и архивирует её; не менять URL на рабочий сайт.

Frontend-проверка дополнительно покрывает людей, курсы, события, вакансии и партнёров: новые адреса uk/de, публикацию/черновик/смену роли/архив, отмену события, компактных преподавателей, sitemap, настоящие импортированные фото, четыре исходных курса, шесть исходных событий, четыре исходные вакансии, семь организаций с логотипами, форму собственной инициативы и связи немецкого курса с Наталией.

`npm run test:cms:delivery` — при уже выполненном `npm run build` и запущенном локальном CMS проверяет production Next.js с HTTPS CMS, переданным после сборки, и реальный static export новых профилей, событий и волонтёрских задач. Использует временный тестовый сертификат, read-only loopback bridge и отдельный порт 3002; TLS-проверка не отключается. **Получившаяся `.pages-out` содержит локальные тестовые адреса: перед выкладыванием обязательно пересобрать с нужной реальной конфигурацией.**

## Границы текущей CMS

Через WordPress пока не редактируются статичные тексты каркаса главной, контакты, юридические документы и банковские реквизиты. Защищённый визуальный предпросмотр черновика отдельно не реализован: редактор проверяет поля и публикует через штатный workflow. Банковские данные намеренно остаются в проверяемой конфигурации проекта, а не в свободном текстовом поле CMS.
